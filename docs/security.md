# Security hardening: dev stack binding, secrets, headers / CSP, rate limits, proxies, dependencies

(Detail moved out of CLAUDE.md: read this when working on the area. Keep it updated with changes.)

## Security (what is locked down and why)

- **Local dev stack is localhost only**: `docker-compose.yml` publishes the API and Vite as `${BIND_ADDR:-127.0.0.1}:...`; `make up` keeps it that way, **`make up-lan`** (`BIND_ADDR=0.0.0.0`, `DEV_MAILBOX=0`) is for phone testing on a trusted Wi-Fi only. The container ports are fixed (3000/5173); the host side can be moved with `HOST_SERVER_PORT` / `HOST_WEB_PORT` (e.g. when something else holds 3000). **Windows `netsh interface portproxy` rules for 3000/5173 (set up earlier for the phone) expose the dev ports to the LAN regardless of Docker and block Docker from binding them**: `netsh interface portproxy show all` (list), `netsh interface portproxy delete v4tov4 listenport=3000 listenaddress=0.0.0.0` (admin PowerShell) removes one.
- `JWT_SECRET` has no default any more: `make env` writes a random one into `.env`; `loadConfig` refuses placeholder secrets (`dev-only`, `change-me`...) in production. The old public dev secret in an existing local `.env` should be replaced (it logs out local players).
- `GET /api/dev/last-mail` (emailed codes for e2e) only exists with `DEV_MAILBOX=1`, `MAIL_MODE=log` and outside production.
- **Real client IP**: `TRUST_PROXY_HOPS` (production; `clientIp.ts` `forwardedClientIp`, also used for sockets) = number of proxies in front. Unset it trusts the whole `X-Forwarded-For` (the leftmost entry, which a client can forge, so rate limits and IP bans can be dodged). Set it in the Render dashboard once the real chain length is known (compare `x-forwarded-for` with `req.ip` in the log after a deploy); a too-high value is forgeable, a too-low one puts everybody behind the proxy's address in one rate-limit bucket.
- **Headers** (`http/securityHeaders.ts`, `onSend` hook): `x-frame-options: DENY`, `nosniff`, `referrer-policy: no-referrer` (recovery links carry a token), `permissions-policy`; in production also HSTS and, on HTML, a CSP (`default-src 'self'`, scripts `'self'` + the sha256 of the inline script in `index.html`, `frame-ancestors 'none'`, `object-src 'none'`...). A new inline script in `index.html` is allowed automatically (hashed at start-up); anything else inline needs a CSP change.
- **Brute force** (`accountRoutes.ts`): at most 3 emailed codes per hour per address and purpose (throttled silently for resets so the answer stays uniform), 10 wrong passwords per address per 15 minutes lock logging in to it for the window (429, `login-locked` in the admin log); the existing per-IP limits stay.
- Dependencies: `pnpm audit --prod` should stay clean; known leftover: `zod` 3.x (memory use on huge collections; inputs are size-capped by Fastify's 1 MB body limit and Socket.IO's buffer). `@fastify/static` 10 passes a Fastify reply to `setHeaders`; `fast-uri` is pinned by `pnpm.overrides`. Render runs `MAIL_MODE=smtp` (nodemailer 10).
- Tests: `apps/server/src/http/security.test.ts`.
