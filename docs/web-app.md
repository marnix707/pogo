## Web app (apps/web)

- Screens are driven by the server's `room:state`: `Shell.tsx` owns the socket (`lib/socket.ts`) and renders `Home` (no room), `Lobby` (status `lobby`) or `GameScreen` (`playing`/`finished`, includes the generic results panel). Screens call the server only through the `RoomApi` object (`lib/api.ts`), and failures are toasted centrally in the shell.
- Game UI plug-in: add a `GameUi` (`games/types.ts`: id, name, emoji, tagline, `Component({room, me, sendMove})`) and register it in `games/registry.ts`. Yatzy lives in `games/yatzy/` (`YatzyGame` = turn banner + `Scorecard` + dice dock with `Die`).
- Yatzy UX: holds are local until you roll; tap a category chip, then tap it again (a double tap) or press "Score" to score it; the roll animation is cosmetic (faces flicker with `Math.random`, real values come from the server). `prefers-reduced-motion` skips animations (the e2e tests rely on this).
- Lobby layout (the room before the game, `Lobby.tsx`; called "Lobby" in the UI, not "waiting room"): **the game card is the top of the lobby**: `GameCard` (`components/GameCard.tsx`) is the very same button as on the Play screen; tapping a game there remembers the card's box (`lib/cardMorph.ts`, `rememberGameCard`) and the lobby's top card (`lobby-game-card`) **morphs** from there to the top (`morphFrom`, 420 ms, off with reduced motion). The card has a ▾ (`game-card-chevron`) and is a button **for everybody** (the host picks, the others suggest): tapping it shows **the very same screen as after Play**: the lobby bar above the card is replaced by the **join-by-code bar** (`JoinBar`, `home-join-code`, the same dark `.calm` look as the lobby bar; the bar comes back when the list closes), and underneath (`PlayScreen`, `components/PlayScreen.tsx`, shared with Home, which shows the join bar on top itself: all games **except the current one** (it is already the card at the top; `pick-game-<id>`), the open games, and a **Main screen** button (`main-screen`) all the way at the bottom that leaves the lobby for the home menu (on Home it is the old back; no intro animation replays); wrapper `game-list`); picking another game as the host sends `room:setGame` and the lobby stays; **as a non-host the pick is a suggestion** (`room:suggest {gameId|null}`, `Room.suggest`, `Member.suggestion`, `RoomMemberView.suggestion`; the same game again withdraws it, the current game cannot be suggested, setting the game or starting a round clears all suggestions): it shows at the very end (right) of the suggester's crew row as "Suggested:" above the game's logo (`suggestion-<gameId>`, `SuggestedGame`); the host taps it to switch to that game; my own lobby shows up in the open games with a **Return** button instead of Join (closes the list, `lobby-join-<code>`); a game that seats fewer people than are in the lobby is greyed out (`aria-disabled`) and tapping it floats "Party size too big!" (`party-too-big`, no background, fades out; the server refuses it too); **Above** the game card a slim toolbar (`lobby-toolbar`): my picture (`lobby-avatar`, opens the profile), **Invite**, space, the leaderboard button (`lobby-leaderboard`), the friends button (`friends-button`) and the settings button (`settings-button`). There is **no back arrow and no "back to game selection" button**: leaving is **Settings > Leave lobby** (`settings-leave`, in `SettingsSheet`, only in a lobby; e2e helper `leaveLobby`). Everything under the card falls in from above, one piece after another (`.lobby-stack`, `lobby-drop`, 360 ms, staggered 60 ms). Then the **Settings** block: a fold (`lobby-settings-toggle`, `aria-expanded`, a chevron on the right of the "Settings ———" label; `lobby-settings` with `data-open`; **folded by default (a fresh lobby, or back from a game: the Lobby remounts) but left as it is when the host switches games inside the lobby**, hidden with `visibility` while folded; e2e helper `openLobbySettings` before touching a setting) holding (1) the **Turn timer** (the game's `LobbyOptions`, e.g. Karma's Normal/Party/Epic `ModePicker`, is no longer in the fold: it sits in its own dark `.calm` card at 80 % opacity right under the game card, `lobby-game-options`, visible to everybody, host-only to change) (`turn-timer`: Off / 30s / 60s / 90s), (2) the host's **Public room** switch (rooms are public by default; the switch is on the right; when the room is **private** its **code** (`room-code`, the only way in) shows under the label, "Anyone in the world can join you" when public; an invisible `room-visibility` text reads Public / Private for tests; the Public/Private rectangle that used to sit in the top bar is gone; the code of a public room is in the Settings sheet as `settings-room-code`), (3) the **Computer players** stepper (games with bots); everyone sees them, only the host can change them (greyed out for others). There is no "Max players" setting: a room always seats the game's maximum. Then Crew (people, then one row per computer player; "Ready ✓" / "Ready 🔒" / "Not ready"), then Chat; the bottom bar (`lobby-bar`, `fixed z-30`) holds only the **Ready button** (`lobby-ready`, the count lives inside it: `lobby-ready-count` "Ready 1/3"; computers are always ready, so they count on both sides: you alone with one computer read "Ready 1/2", with a ✓ when I am ready, plus `lobby-countdown` "Starting 3…"; **one person with computers, or alone in a solo game (Yatzy), has no countdown at all**: the button reads plain "Start" (`startNow`) and the server begins the game at once when that person is ready (`Room.startsInstantly`, checked in `changed()`); when the game needs more seats than people + computers there are, a small second line inside the button (`lobby-need-players`) says "Not enough players or computers: need N", and for the **host** of a game with computers the button reads "Add Robo 🤖 0/1" (`data-mode="add-robo"`) until the seats are filled: tapping it adds a computer (`updateSettings {bots+1}`), after which it is the normal Ready button again (other players keep "Ready")) and, once I am ready, an **open padlock** (`lobby-ready-lock`, `aria-pressed`): tapping it **locks Ready** (`room:readyLock {locked}`, `Member.readyLock`, `RoomMemberView.readyLock`): a locked Ready survives a setting change, a switched game and coming back from a game (`Room.resetReady()` keeps locked members ready), so a group cycles through games without re-pressing; cancelling Ready unlocks. **Nobody starts a game by hand**: the server starts it 3 s (`START_COUNTDOWN_MS`, `limits.startCountdownMs` in tests) after everybody present is ready and the seats (people + computers) reach the game's minimum; un-readying cancels the countdown; the host changing a setting resets everybody's Ready (except locked ones); a newcomer is not ready; computers are always ready. Protocol: `room:ready {ready}`, `room:readyLock {locked}`, `RoomMemberView.ready|readyLock`, `RoomView.startsAt`; `Room.start(userId)` remains host-only for the "play the computer" create flow (`autoStart`) and tests; the lobby uses `setReady` + `evaluateStart()`. E2E: `readyAll(...pages)` in `e2e/tests/karma-helpers.ts`, `persistent-lobby.spec.ts`. The "open games" list on Home is a different thing (the server's `lobby` channel).
- Home layout: header row: **my picture top left** (`home-avatar`, opens the profile; the same `Avatar` tile as in the crew list: the picture fills a rounded tile with the gold ring and the dark outline) with "Playing as <name>" (`home-nickname` inside `home-playing-as`) that swipes out next to it for 5 seconds when the screen is there and slides back (`data-open`; no transition with reduced motion), and on the right the leaderboard (`home-leaderboard`) and settings (`settings-button`) (the small logo tile is gone, the wordmark is the logo), the install banner, and one big button at the **bottom** of the screen: **Play** (`home-play`, a gold-orange filled `Button variant="gold"`). The **Play screen** has, top to bottom: the join-by-code form (`home-join-code`, `home-join-submit`), the games list, and the **Open games** list underneath (filter chips + live list; `open-game-<code>`). The Play screen has **no top bar** (profile, leaderboard and settings are on the menu only): its first bar is the join bar, at the same height and place as the lobby's top bar (`pt-[calc(env(safe-area-inset-top)+1.25rem)]`, 4rem tall), so nothing jumps between Play screen, game selection and lobby. There is no Join button and no visible Back button any more (`home-join` / `home-back` are gone; the back gesture / edge swipe / browser back still return to the menu through the history entry; a Back button may return later). Play is a browser-history entry (`pushState`), so the phone's back button/gesture returns to the menu, and a swipe from the left screen edge does the same inside an installed app (`Home.tsx`, `home-back`). Above the Play button a small line "There are N players online" (`home-online`, hidden at 0; `GET /api/online` counts users with an open socket, polled every 30 s). Under the Play button a credit line (`home-credit`): "Developed by <developer display name>" with a smaller "(and Claude)" (the name comes from `GET /api/credits` = the account of the first `DEV_EMAILS` address, cached 5 min; "Developed with Claude" when there is none). The game list shows one tappable card per game with its tagline (`home-game-<id>`). Tapping a game creates a room and goes straight to its lobby (no menu): see "Lobby layout" above for what the lobby holds (settings fold, crew, chat, the Ready / Start button). The old Quick match / With friends / Play the computer menu is gone (the `quickPlay`/`playComputer` API calls remain, unused by the UI). `Sheet` (`components/ui.tsx`) slides up over a dimmed backdrop (`bg-black/60`, `sheet-backdrop`) and slides back down when you tap outside or the X; it stays mounted for `SHEET_MS` (220ms) while sliding away, so **tests that close a sheet and then open another must wait for `getByRole('dialog')` to have count 0**. E2E tests tap `home-game-<id>` and are in the lobby; computers are added with the `More Computer players` stepper button.
- **Play again** (solo: one person in the room, with or without computers): the results screen shows a gold `Play again` (`results-again`, `room:rematch {toLobby:false}` = the host restarts at once with the same people and computers; `Room.rematch`) above Lobby and Exit.
- **Automatic next game**: when a game ends and **every person still in the room has Ready locked**, the next game starts by itself (`Room.autoNextEligible`, `autoNextAt` in `changed()`/`tick()`, `RoomView.autoNextAt`, `AUTO_NEXT_MS` 12 s = the results stay, `limits.autoNextMs`; it goes through `rematch(host, true)` and `begin()` at once, with no stop in the lobby; the game's `nextOptions` apply). It stops when somebody unlocks, leaves, or a newcomer joins (not locked). The results screen then shows "Keep playing: next match starts in Ns" (`results-next-match`) with **Leave next match** (gold, `results-leave-next`: takes my lock off, which stops the loop for everybody, and the normal Lobby / Exit buttons come back) and a red **Leave game** (`results-leave`); `setReadyLock(false)` is allowed on the results screen. Test: `RoomManager.test.ts` "automatic next game".
- **Persistent lobby**: the room outlives the game choice. In the lobby the **host taps the game card at the top** (`lobby-game-card`) and picks another game from the list that drops in (`pick-game-<id>`) instead of leaving; picking a game sends `room:setGame {gameId}` (`Room.setGame`, host only, lobby only, refused when more people are seated than the new game's maximum): the room keeps its code, members, chat, visibility and timer; the game's options go back to its defaults, computer players are kept only if the new game takes them and fits, and everybody's Ready is reset. The others see the new game at once (`room:state`) and a toast "The host switched to X"; everybody leaves through Settings > Leave lobby. Together with the results screen's **Lobby** button a group cycles through games without leaving. Errors ROOM-124/125. E2E: `persistent-lobby.spec.ts`.
- `Sheet` (`components/ui.tsx`) takes `from?: 'bottom'|'top'` and `dim?: boolean` (default bottom, dimmed). The Settings sheet comes down from the top, only as tall as its content, with no dark overlay (`from="top" dim={false}`; the transparent backdrop still closes it on an outside tap; `.sheet-panel-top`, `sheet-from-top`/`sheet-to-top` in `index.css`). The panel className is a template literal (it used to be a plain string with a literal `${full ...}`, so `max-h`/`overflow`/`full` never applied).
- Settings (sound, vibration, CRT strength) are in `lib/settings.ts` (localStorage `pogo.settings`); sounds are synthesized with WebAudio (`lib/sound.ts`, no audio files); haptics use `navigator.vibrate` (`lib/haptics.ts`).
- Yatzy banner: no purple any more (the normal slate panel like the lobby's top bar; my turn is only marked by the gold border); the three "rolls left" dots are **not in the banner** but small **below the dice, between them and "<name> is playing…"** (`rolls-dots`, inside the 44px opponent line so the layout rule below still holds) and **only while somebody else is on turn** (on my turn the Roll button says how many are left).
- Yatzy has no shared title bar (`GameUi.ownHeader`): the turn banner is the only header, with leave arrow (`leave-game`) at the left and chat (`chat-open`) + settings (`settings-button`) at the right, wired through `GameUiProps.chrome` from `GameScreen`. The room code is shown in the Chat sheet title and as the first row of the Settings sheet (`roomCode`, `settings-room-code`); the game's top bar no longer carries a "Room …" subtitle. Scorecard: a 0 looks like any other score (bold); a thin spacer row separates the upper and lower parts; the Bonus row shows `my subtotal/63 · +35` in its label and each player's subtotal (or `+35`) in the cells.
- Yatzy dice: the artist's pixel-art SVGs (`assets/sprites/dice/die-1..6.svg`, drawn by `Die.tsx` as an `<img>`, `imageRendering: pixelated`); each face has its own colour (1 white, 2 yellow, 3 blue, 4 red, 5 green, 6 purple; `DIE_COLOR` in `Die.tsx` holds the same colours for the scorecard's colour squares, keep them in step). A held die is lifted and gets a gold drop-shadow outline; a not-yet-rolled die is the 1 face greyed. Keeping a die sends a free `hold` move (`GameDefinition.isFreeMove`: does not restart the turn clock) so opponents see it at once. After a roll the kept dice sit on the left (display `order` in `YatzyGame`, FLIP slide) and new dice fly in from the right.
- **Yatzy fire** (`Flames.tsx`, the artist's lo-fi fire in `assets/sprites/fire/`: 8 flame frames `fire-lofi-flame-00..07.svg` 18x24 art px at 100 ms, plus long `fire-lofi-strip-*.svg` 32x14 tiles that are not used yet): a Yatzy scored as 50 burns behind its number (`Flames`, `yatzy-flames`, `data-fire`); level = number of Yatzys hit (1 + bonuses, from `getTotals(...).yatzyBonus / 100`, so it follows the scoring animation's held totals): each hit makes the flame bigger, 3+ adds a second flame, 5+ a third (capped at 6); static frame with reduced motion. There is no Yatzy bonus row: each extra Yatzy adds 100 to the number in the Yatzy box (50, 150, 250...) and the flame grows; level 1 is already a medium flame (`scale = 0.6 + level * 0.3`). The old CSS pixel fire (`FireText`) is gone.
- The Yatzy Roll button is greyed out (and `roll()` refuses) while the dice are still rolling (`settled`), so a double tap cannot roll twice by accident.
- The Yatzy results wait for the last box's scoring animation (`resultsDelayMs` 3.4 s: flights up to ~2.2 s plus a moment to look at the final card and any Yatzy fire) when the game ends live.
- **Yatzy scoring animation** (Balatro style, `ScoreFx.tsx`, `useScoreFx(state)` in `YatzyGame`; off with reduced motion): a newly filled box is detected by diffing the state with the previous one (so it runs for every player; the dice come from the previous state, their on-screen boxes from `die-<i>`). The dice that count (`yatzy.scoringDiceIndices`: the face for the upper boxes, the four dice of a small straight, all five otherwise, none for a 0) fly as miniature dice in random order, 110 ms apart (280 ms flights), to the box (`cell-<playerId>-<category>`); each arrival pops a white bold number with its own drop shadow showing the running total (+3, +6, +9... fixed-score boxes are spread evenly), growing from 11px (1 die) to 22px (5 dice), a little bigger than the box; then it tips 45 degrees to the left (220 ms, a smooth click) and falls (300 ms) back down into the total, ending upright at 0 degrees (`total-<playerId>`), where the total **turns white**, soaks the landed number up (it shrinks into the total) and races up to its new value in 560 ms, casino style (an eased count with rising-pitch ticks, `tick()` in `lib/sound.ts`), and pulses bolder and relaxes (`.score-bold`, a same-coloured text shadow because the font has one weight). While it runs the `Scorecard` holds the new box and the totals back (`fx` prop: `holdCell`, `bonusesBefore`, `totalShown`, `pulseKey`). A 0 just pops a grey 0 into the box.
- Yatzy extras: the Roll button carries the turn clock as a draining `TimerDrain` bar (like the header banner), and while somebody else is on turn their column shows what their dice could score in small grey type (`hint-<category>` in `Scorecard`, from `yatzy.getPreviewScores(state.dice, theirScorecard)`; never on my own turn). The winner of a game with more than one player gets confetti on the results screen (`components/Confetti.tsx`, `ResultsPanel` `confetti` prop; Karma too: its win reveal has confetti for a last face-down card, but a last card from hand/face-up has no reveal, so the results panel is where every winner gets confetti).
- Yatzy layout rule: the whole scorecard + dice + buttons must fit one screen without vertical scrolling at 390x700 (enforced by an e2e test). `YatzyGame` measures the free space (ResizeObserver) and passes `fillHeight` so the table's rows stretch to use it; row/chip heights are deliberately tight (24px) and there is a denser variant under `max-height: 640px`. Horizontal scroll (many players) is fine. Avoid inline content in table cells (line boxes add height): keep cells `h-6 leading-none` and chips `block`.
- Stable `data-testid`s (e.g. `roll-button`, `pick-<category>`, `score-button`, `turn-banner`, `results-panel`) are used by the e2e tests; keep them when refactoring.


## Installable app / PWA (apps/web)

- Install = "Add to Home Screen": `public/manifest.webmanifest` (standalone, portrait, blue `#1f4f8c` colours, icons 192/512 + maskable), iOS meta tags in `index.html` (`apple-mobile-web-app-capable`, title, `black-translucent` status bar, `viewport-fit=cover`), `apple-touch-icon.png`. Icons are rendered from the logo with Chromium (`icon-maskable-512.png` keeps the art inside the central 80% so Android's circle crop can't clip it).
- Top spacing under the status-bar scrim must be `calc(env(safe-area-inset-top) + X)`, NOT `max(X, env(...))`: with `max` the header sits flush against the scrim on a notch phone (the logo looked glued to the top). `TopBar` uses +1.25rem (normal) / +0.5rem (compact), so the space above the logo equals the ~20px below the title.
- Fullscreen on iOS: launched from the icon the page runs under a translucent status bar; `.safe-top-scrim` (fixed, `height: env(safe-area-inset-top)`, navy) fills that strip and is 0px in a normal browser. Layouts already use `env(safe-area-inset-*)` for top bars and bottom docks.
- `public/sw.js` (registered in `main.tsx`, production builds only): network-first for pages with a cached shell fallback, cache-first for fingerprinted `/assets/*`, never touches `/api/` or `/socket.io/`. It is served `no-cache` so updates roll out; bump `VERSION` to drop old caches. Service workers need HTTPS or localhost, so they are inactive on the plain-http LAN dev URL (iOS "Add to Home Screen" still works there) but active on Render.
- iOS gotchas: iPhone bakes an icon's settings in on the day it is added, so an icon added before the manifest/meta tags existed keeps opening in a browser tab until it is deleted and re-added (preferably from Safari). Settings shows a live status (`DisplayModeNote`: "Running as an app (fullscreen)" vs "Running in a browser tab") so this can be checked on the device, and the iOS install steps say so. `iosThirdPartyBrowser` (CriOS/FxiOS/EdgiOS) adds a hint to use Safari.
- **Update notice** (a deploy while the app is open): a running page cannot swap its own code, so `vite.config.ts` gives every build an id (`__BUILD_ID__`; `RENDER_GIT_COMMIT` when set, else a timestamp) and writes it to `version.json` in the dist (the dev server serves it too; `static.ts` already serves it `no-cache`). `lib/updateCheck.ts` (`useUpdateAvailable`: every 2 min while visible, when the tab becomes visible and on `online`) compares it with the page's own id; when it differs `components/UpdateNotice.tsx` (mounted in `App.tsx`, `update-notice`) covers everything with a dark backdrop and "You are using an older version of POGO. Please reload" with **Reload now** (`update-reload`) and **Later** (`update-later`, hides it 5 min). Nothing to bump by hand. E2E: `e2e/tests/update-notice.spec.ts` (mocks `/version.json`).
- In-app help: `lib/install.ts` (`useInstall`: standalone / iOS / `beforeinstallprompt` captured for a one-tap Install) and `components/InstallCard.tsx` (dismissible banner on Home + a row in Settings; iOS shows the Share → Add to Home Screen steps, hidden when already installed). Tests: `src/pwa.test.ts`, `e2e/tests/pwa.spec.ts`, server static tests.


## Visual design (apps/web)

- Look: a card-table at night, a homage to the Balatro style with original art only (no game assets, name or logo); colours come from the Balatro modding palette. Deep blue page `#1f4f8c` (gradient `#2c78c8` to `#20325a`) with a static soft red/purple/gold glow (`body::after`) and **contour lines that drift, morph and breathe** (`components/TopoBackground.tsx`, a fixed canvas behind everything: a seeded 3D-noise height field `lib/topo.ts` drawn as marching-squares iso-lines at ~24 fps, 22 levels with an index line every 5th, dark blue strokes; 0.035 height units of breathing over 16s; pauses when the tab is hidden, a single still frame with reduced motion; `lib/topo.test.ts`). Blue-slate panels `#334461` (`panel`; `panel2` `#24324b`) with a periwinkle inner line (`edge` `#899ad1`), a near-black blue outline `--c-line` `#101628` and a hard lip under them, gold-orange `#fda200` highlights (`neon`; plus `orange` `#ea9600`), bright blue `#3cb4ff` primary actions (`accent`, dark text on it, lip `#0081d3`), red `#c14139` fills / `#fda0a5` red text (`danger` / `dangertext`), purple `#7d51ae` for "your turn" (`grape`), green `#459373` (`lagoon`). Contrast was checked (text on panels >= 5.8:1, dice on the dock >= 3.2:1, pips >= 5.2:1). One theme only: the old light/dark switch is gone; Settings has a **CRT effect slider** 0-100 in steps of 5 (default 0 = off; `html.crt::after`: scanlines + dark edge whose `opacity` is the `--crt` variable, `pointer-events: none`; saved as the number `crt` in `pogo.settings`, an old saved boolean counts as 0; applied before first paint in `index.html`). `prefers-reduced-motion` stops the contour lines and card wobble.
- Colors are CSS variables (`--c-*` "r g b" triples in `src/index.css`, `:root` only) exposed as Tailwind colors in `tailwind.config.js`: `page panel panel2 edge ink muted onbg accent accentink neon lagoon grape danger dangertext line`. Use these semantic names, never raw slate/violet colors.
- Shared classes in `index.css`: `.hud` (slate panel: inner line, dark outline ring and lip via box-shadow, `rounded-[10px]`), `.hud-ticks` (a second gold inner frame on a `.hud`), `.label` (tracked uppercase caption). Components live in `components/ui.tsx` (Button with a coloured lip that squashes on press, Card, SectionLabel, Avatar dial, Sheet, Toggle), icons in `components/icons.tsx`. Cards: `PlayingCard.tsx` (cream face `#f7f1e4`, blue diamond back `#009cfd` with a gold frame, selected cards wobble via `card-wobble`); dice: `Die.tsx`.
- Font: `PogoPixel` = `src/fonts/pogo.otf`, a pixel font under the SIL Open Font License 1.1 (copyright notice + license in `src/fonts/OFL.txt`, which must stay next to the file; keep the file unmodified, never sell it by itself, don't use the author's name to promote the app). Only a regular weight exists, so `font-synthesis: none` stops faux bold. Fallbacks: Pixelify Sans (`@fontsource/pixelify-sans` 400/700) for missing glyphs, then system fonts (suit symbols and emoji come from the system font). The logo/app icon is the artist's frog tile (`assets/icons/icon.svg`, see the assets section); `sw.js` `VERSION` is bumped when the look changes.
- Name: the product is written **POGO** everywhere (UI, manifest, meta tags, emails); it was "Po:go" earlier. Repo/package names stay `pogo`. `RaisedColon` (`components/Brand.tsx`) is now only a pass-through helper for text without colons.
- Logo: the frog on a yellow tile with a dark border and stepped rounded corners (`assets/icons/icon.svg`; `icon-flat.svg` is the full-bleed, borderless original used for `apple-touch-icon.png` (192px): iOS rounds the corners itself and paints any transparent or dark border area black, so that icon must have neither). The PNG icons were generated from the same pixel grid with a small Python script (no renderer in the containers); regenerate the same way when it changes.
- After changing `tailwind.config.js` the Vite dev server must be restarted (`docker compose restart web`) to pick it up.


## Opening animation (Home menu, `components/PogoStage.tsx`)

- The mascot is **Pogo the toad** (earlier drafts said frog; file and test names such as `sfx_frog_croak_single` and `animation/` keep the old word). Once per page load (module flag `introPlayed`, set when the toad lands **or by `markIntroSeen()` when the player leaves the menu on purpose** (entering a game room in `Shell`, opening Play or Join in `Home`): coming back with a back arrow / "Back to game selection" never replays it, even if he left mid-intro; a plain unmount does not count because the menu remounts briefly while connecting; with reduced motion it is skipped and the final state shows at once, which is why the e2e tests, which use reduced motion, never wait for it): the menu starts as an empty screen with only the pogo stick (`pogo-stage`) in the middle; the toad (side view) hops in from the left (`hop_in`, `mount` of `pogo-side-animation.json`), the landing switches to the front view and he bounces `AUTO_BOUNCES` (3) times, then rests (`pogo_extend`); from then on he only jumps when tapped (`pogo-jump` button over him: one `pogo_loop` cycle, one `pogoHit` sound). At the landing step `onLanded` flips `landed` in `Home`: the wordmark (`wordmark-die-o.svg`, POGO with a die as the last O, `home-wordmark`) pops in from scale 0 and then breathes +-5% (`.wordmark-in`, `index.css`), always tilted -10 degrees with clear space above the toad's head (no overlap); the whole group sits higher than centre (`pb-20`); the header slides in from the top and Play/Join + "Playing as" from the bottom (`.slide-top` / `.slide-bottom`, `data-in`). The **logo is placed exactly halfway between the bottom of the top bar (or the install banner when it shows) and the highest point the toad reaches** (`PEAK_ART` = 45 art px above the bottom of his stage: `pogo_air` at y -14, top row 1 of 32): Home measures the three boxes in a layout effect and absolutely positions the wordmark (`flat`: no clear space under it) at that midpoint plus 10px (`wordMid`, `LOGO_NUDGE`: the tilted corner clipped into the top bar). The toad is drawn 30% smaller than a whole-number scale (toad 4.375 / wordmark 11, or 3.5 / 8.8 scaled by `height / 700` under 700px height so Play and Join still fit; pixel art at a fractional scale is slightly uneven, that is accepted). While sound is blocked by the browser the stage shows "Tap to start" at the top of the stage, above the stick (`top-2` **inside** the stage: the stage root has `overflow-hidden`, so a label placed outside its box is clipped and invisible), and waits for the first tap. Headless Chromium starts with audio unlocked, so a test must suspend the `AudioContext` to see it.
- Timeline: all frames are stacked as `<img>`s with `visibility` toggled (no flicker while loading), steps come from the JSON (x/y art px relative to the stick, anchor bottom-centre, fx sprites with sizes in `FX_SIZE`). Sounds: `frogJump` on the first leap frame of each hop-in jump, `pogoHit` on every `pogo_compress` step (the landing too). Returning to the menu later shows him resting.
- `e2e/tests/intro.spec.ts` plays the real animation (motion enabled) and writes screenshots to `e2e/test-results/`.


## Chat banner, reveal spoilers and new games (Karma)

- `ChatBanner` (`components/ChatBanner.tsx`, mounted in `Shell`, `data-testid="chat-banner"`): a chat message from somebody else slides down from the top like a notification, as high as the header (`3.5rem` + safe area), one line cut off with `…` (`truncate`), 3.6s (`chat-banner` keyframes in `index.css`, off with reduced motion), tap to dismiss. History loaded on joining is not announced (only appended messages, or the first message of a fresh room).
- While a card turns over (`reveal`, or the render before it is set: `revealPending`) `KarmaGame` shows **no turn information**: `myTurnShown`/`shownTurnId` keep the flipper as the current player, so the hand is dimmed, nothing is highlighted as playable and the turn ping waits; otherwise you could tell from your own turn whether the flip was too low (the flipper keeps the turn and must pick up) or fine.
- The result sound of a last card and the winner's fanfare play when the card has finished turning (`TURN_MS`, `GameUi.ownFanfare`: `GameScreen` then stays silent; other games play it when the standings appear).
- `GameScreen` mounts the game component with a key that changes every time the room goes to `playing` again, and `KarmaGame` clears the card position cache (`resetFlipBoxes`), so an instant rematch starts from a clean UI (state of the previous game, such as old selections or card positions, used to leak into the new one).
- The robot icon is reserved for computer players (`BOT_AVATAR`; not in `AVATARS`, so nobody can pick it; accounts that had it get the fox in `toPublic`). Avatars are **square tiles** (`Avatar` in `components/ui.tsx`, `rounded-[6px]` with the dark outline). On Home, tapping your own icon (`home-avatar`) opens a `Sheet` with square tiles (`pick-avatar-<id>`); picking one saves it with `PATCH /api/me` (`updateProfile` in `lib/session.ts`, `App` keeps the user in state through `Shell`'s `onUser`). It only changes on Home: a room keeps the icon the player joined with.
- **Menu boxes are gold-orange** (`.menu` on the Home and Lobby roots and on every `Sheet` dialog): inside a `.menu .hud` the tokens are re-pointed (`panel` `#fda200`, `panel2` `#ea9600`, `ink` navy, `muted` brown, `neon` navy, `accent` deeper blue with white text, `dangertext` dark red), so no component needs to know; things on the table outside a box and the game tables (Yatzy dock and scorecard, Karma, results) keep the blue-slate panels.
- **Cards are the artist's pixel-art SVGs** (`assets/sprites/cards/`, 45x61 art px; `games/karma/cardArt.ts` maps a card number to its file: suit index 0-3 = S,H,D,C, rank 2-14 = 2..10,J,Q,K,A; `back.svg` is the back). `PlayingCard` draws an `<img>` stretched to its 5em x 7em box (3% off the art ratio, invisible) and applies dimming, the selection outline (gold drop-shadows) and the lift shadow as CSS `filter`s, because the art has its own rounded outline. The old code-drawn faces and `PixelSuit` are gone: to redesign a suit or a card, replace the SVG (see the assets section).

- **Portrait only**: the manifest says `portrait`, `main.tsx` tries `screen.orientation.lock('portrait')` (installed app / fullscreen), and a phone held sideways in a browser (landscape, under 500px high, coarse pointer) is covered by `.rotate-notice` ("Turn your phone upright", `App.tsx`, `index.css`). The sheet grabber (`DetentSheet`) is the pixel sprite `assets/sprites/ui/sheet-grabber.svg`, made with the pogo-pixel-art skill.

- **Info / invite / top bar** (`.info-bar`, `index.css`): the panel above the game card in the lobby and the join bar on the Play screen: 4.75rem tall (was 4rem: the icon buttons' lip overlapped the bottom border on a phone), icons keep their size, extra padding below; same height in both so nothing jumps. Games use `TopBar` (the game's logo in place of its name).
